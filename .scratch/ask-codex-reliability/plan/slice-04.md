## Outcome

1. **Live tooling** (new, under `.scratch/ask-codex-reliability/plan/`, nothing shipped):
   - `live-04-watch.mjs` — started before a scenario, given the workspace path. Polls once per second with `Get-CimInstance Win32_Process` (fields `ProcessId`, `ParentProcessId`, `Name`, `CreationDate`, `CommandLine`). Records: the baseline set of `codex.exe` pids; the scenario's `codex.exe` (command line contains the workspace path) and, from its `-o '<run dir>/last-message.json'` argument, the run directory; the Windows pid in `<run dir>/pid` and the **union of every descendant ever seen** under it (pid + `CreationDate`, so a reused pid is not mistaken for a survivor); and each member's **last-seen time**. A second, cheap loop (`fs.stat`, every 250 ms, no process query) records the size of `<run dir>/events.jsonl` and the first time each of `<run dir>/stop-request`, `<run dir>/stop-report` and `<run dir>/last-message.json` exists, until the directory disappears. Three moments are derived: **stop requested** (`stop-request` first exists), **chain gone** (first process sample in which no chain member is alive), **reported** (`stop-report` first exists — `stop.sh` writes it only after its kill, its verification and its own 5 s window). After the stop request it keeps sampling processes for 65 s, then writes one JSON file: the chain with last-seen times, the three moments, which members were alive at +5 s and +60 s after the stop request, the `codex.exe` pid set at +60 s versus the baseline, the `events.jsonl` size series, and the **quiet window** — from *chain gone* until the run directory disappears — with its length in seconds and its sample count. It stores command lines only for the scenario's own chain.
   - `live-04-check.mjs` — reads that JSON plus the scenario's reply text. **Pass (exit 0)** needs all of: a stop request was seen; the chain had at least `sh/bash → node → codex.exe`; **every chain member's last-seen time is no later than *reported*** and no later than 15 s after the stop request (`stop.sh` may wait up to `RESULT_WAIT_S` = 10 s); no member alive at +60 s; `codex.exe` set at +60 s ⊆ baseline; `events.jsonl` size constant over the quiet window, which has **at least 8 samples spanning at least 2 s** (an event flushed between the stop request and *chain gone* is allowed and reported); `last-message.json` never appeared; the reply contains a `Consultation stopped:` line ending `process tree ended` (regex; "nothing attributed to Codex" is read by the main session and the verifier). The +5 s sample is always recorded; a member alive at +5 s that is gone before *reported* is a pass with the kill duration noted — a member that outlives *reported* (for example one that only dies when the headless session exits) is a failure. Exit codes, each asserted by its own synthetic case:

     | Exit | Shape | Disposition |
     |---|---|---|
     | 0 | all of the above | scenario passes |
     | 3 | the run finished before any stop request (`last-message.json`, no `stop-request`), or `last-message.json` appeared within 2 s of the stop request (a race with a run that was completing) | not a stop scenario: retry with the heavier question; counts against the call cap |
     | 4 | the watcher never identified the run directory or a `sh/bash → node → codex.exe` chain | invalid run, tooling defect: fix the watcher offline, retry once; counts against the cap; a second exit 4 → pause and ask |
     | 5 | quiet window has fewer than 8 samples or spans less than 2 s | inconclusive on the growth point only: retry once; counts against the cap; a second exit 5 → pause and ask (offering a claim narrowed to the process evidence) |
     | 6 | processes ended in time but the reply has no `Consultation stopped:` line | skill-behaviour finding (ticket 03 measured the final restatement at 14/15), P2, recorded in the ticket, not fixed here; the process evidence is kept; retry once for the full claim; a second exit 6 → pause and ask |
     | 10 | **P1**: a member outlived *reported* or the 15 s bound, or is alive at +60 s; `events.jsonl` grew inside the quiet window; a `codex.exe` outside the baseline at +60 s; `last-message.json` appeared more than 2 s after the stop request; the reply's line ends `process tree NOT confirmed` | keep all evidence, pause, ask (see Budget and stops) |

   - `live-04-check.test.mjs` — offline, written first (red → green), one synthetic JSON per row above and per P1 shape, plus: an event flushed between stop request and *chain gone* (must pass), alive at +5 s but gone before *reported* (must pass), gone only after *reported* (exit 10), pid reuse with a different `CreationDate` (must pass), too few quiet-window samples (exit 5).
